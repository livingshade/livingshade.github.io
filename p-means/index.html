Code Benchmark protocol

p-means is a GPU k-means trainer for large k. It builds on o-means and uses a recency-weighted mean for the final centroids at every training budget. One rule covers all eight datasets from the e-means paper.

On an NVIDIA H100, p-means reached the paper’s held-out error target on all eight datasets. The geometric mean speedup over e-means was 2.76×. The results show all eight comparisons.

What changes in p-means

e-means uses mini-batch exponential moving averages (EMAs) to update centroids. o-means adds a two-level search over the centroids. p-means keeps that search and changes the final averaging step and the GPU kernels.

Closing mean
At every training budget, the final centroid is the ratio of an EMA of sums to an EMA of counts. The rule uses a half-pass window on all eight datasets.
GPU kernels
The scan uses wider tiles, and batch sums are grouped by centroid before accumulation. Cell rebuilds also avoid a host read-back.
One rule
The search probes four cells. Batch size depends on the number of rows, with 65,536 at one million and 262,144 at ten million.

Results on one H100

For each seed, the error target is the held-out MSE of Flash-KMeans after 25 iterations. On DINOv3 10M, p-means reached that target 218.5× faster than Flash-KMeans.

How the benchmark was run

Flash-KMeans and e-means use the paper’s H100 reference numbers. o-means uses its defaults and p-means uses the shared rule. Both were measured on one NVIDIA H100 80GB. Each seed’s speedup is the Flash-KMeans@25 time divided by the time at the first tested budget that reaches its held-out MSE.

The rule was selected using seed 10, which is also part of the evaluation. The 1M runs use ten seeds and the 10M runs use three. One e-means rerun on DEEP* 10M took 0.519 s here, compared with about 0.569 s implied by the paper. The SPACEV rows came from a second session, where a reference run was about 8% slower.
